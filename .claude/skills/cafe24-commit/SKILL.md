# /cafe24-commit

변경사항을 규칙 위반 없이 커밋하고, 필요하면 push·PR까지 진행하는 git 워크플로우.

## 절차

1. **규칙 준수 확인 (게이트).** `/cafe24-review`와 동일한 절차로 `.claude/rules/hard-rules.md` 기준 변경분을 검토한다. 위반(⛔)이 하나라도 있으면 여기서 멈추고 사용자에게 보고한다 — 위반 상태로 커밋을 진행하지 않는다.
2. **스테이징 대상 확인.** `git status`로 변경/미추적 파일을 모두 보여준다. 의도치 않은 파일(임시 파일, 개인 설정, 큰 바이너리, 민감정보로 보이는 파일)이 섞여 있는지 사용자와 함께 확인하고, 특정 파일명으로만 `git add`한다 (`git add -A`/`git add .` 지양).
3. **커밋 메시지 작성.** `git diff --cached`와 `git log --oneline`(과거 커밋 스타일)을 참고해 "왜 바꿨는지"에 집중한 1-2문장 커밋 메시지를 작성한다. heredoc으로 커밋하고, 마지막 줄에 `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`를 남긴다. 사용자가 명시적으로 커밋을 요청한 경우에만 이 단계를 실행한다.
4. **원격 확인.** `git remote -v`로 원격 저장소 존재 여부를 확인한다.
   - 원격이 없으면: 로컬 커밋까지만 완료했다고 보고하고 종료한다 (제출은 zip으로도 가능하므로 원격이 필수는 아니다). 사용자가 원하면 원격 추가 방법만 안내한다.
   - 원격이 있으면: 5번으로 진행하되, **push와 PR 생성은 반드시 사용자에게 먼저 무엇을 할지 요약하고 확인을 받은 후에 실행한다** (이 저장소는 개인 과제 제출용이라도, push/PR은 공유 상태에 영향을 주는 작업이므로 매번 확인).
5. **push + PR (원격이 있고 사용자가 동의한 경우만).**
   - 현재 브랜치가 원격에 추적되지 않았다면 새 브랜치로 `git push -u origin <branch>`.
   - `gh pr create`로 PR을 생성한다. 제목은 70자 이내, 본문은 Summary(불릿) + Test plan(`/cafe24-qa` 체크리스트 상태 요약) 형식으로 작성한다.
   - `--force`, `--no-verify` 등은 사용자가 명시적으로 요청하지 않는 한 절대 쓰지 않는다.
6. 마지막에 어디까지 진행됐는지(커밋만 / push까지 / PR까지) 한 줄로 요약한다.

## 하지 않는 것
- 사용자 요청 없이 커밋하지 않는다.
- `git reset --hard`, `git clean -f`, `git push --force` 등 되돌리기 어려운 명령은 이 스킬의 범위 밖이다 — 필요하면 사용자에게 별도로 확인받는다.
