# /cafe24-qa

이 과제(카페24 골라담기 옵션 UI)의 진행 상황을 코드 기준으로 점검하고 QA 리포트를 작성한다.

## 절차

1. 프로젝트 루트의 `CLAUDE.md`를 읽어 절대 규칙과 9개 체크리스트, 제출물 요건을 다시 확인한다.
2. `detail.html`을 읽는다. 존재한다면 옵션 UI 관련 설정 JS/CSS 파일도 함께 읽는다.
3. 아래 9개 항목 각각에 대해 코드를 근거로 판정한다. 표시는 다음 세 가지 중 하나:
   - ✅ 코드상 구현이 확인됨 (근거 라인/코드 인용)
   - ⚠️ 코드만으로는 판단 불가 — 실제 스토어프론트에서 수동 확인 필요 (특히 아래 항목은 런타임 동작이라 반드시 시크릿 창에서 직접 확인하고 GIF/영상으로 남길 것: **#2 동기화, #3 중복 방지, #4 횟수 제한, #7 활성화 상태 표시**)
   - ❌ 코드상 미구현 또는 누락

   | # | 요구사항 |
   |---|---|
   | 1 | 골라담기 형태 커스텀 옵션 UI 정상 노출 |
   | 2 | 커스텀 옵션 선택 시 카페24 기본 텍스트버튼 옵션의 선택 상태·구매 흐름과 함께 갱신 |
   | 3 | 옵션 선택 후 선택상품 목록 정상 생성, 반복 클릭·재선택 시 오류/중복 없음 |
   | 4 | 옵션값 suffix(_1,_2) 기준 개입수별 추가 가능 횟수 제한 |
   | 5 | 개입 수별 금액/추가금액 정확히 계산, 옵션값 수만큼 상품 품목 모두 생성 |
   | 6 | 수량 변경, 총금액 계산, 장바구니 담기, 바로구매 정상 동작 |
   | 7 | 선택된 옵션의 활성화 상태가 사용자에게 명확히 표시 |
   | 8 | 옵션별 뱃지·설명·추천문구·추가가능횟수·가격표시 등이 외부 설정 JS로 분리 |
   | 9 | PC/모바일 반응형에서 옵션 UI 레이아웃 안 깨짐 |

4. 스코프 위반 여부를 별도로 점검한다:
   - 옵션 영역 외 마크업(상품 이미지, 상세설명, 배너, 구매버튼 외형 등)이 수정되었는가?
   - 카페24 기본 구매/장바구니 로직에 필요한 DOM·이벤트(`module="product_action"`, `{$action_buy}`, `{$action_basket}`, `{$form.option}`, `{$form.quantity}` 등)가 삭제되지 않았는가?
   - 외부 설정 JS가 옵션 UI 구성값 관리 외의 용도(구매 로직 대체 등)로 쓰이고 있지 않은가?
   - 계정 정보·API 키 등 민감정보가 코드에 남아있지 않은가?
5. 제출물 체크리스트도 함께 확인한다: 스토어프론트 URL 확보 여부, Git/zip 준비 여부, README 3항목(구현 방식/설정 JS 구조/동기화 방식) 작성 여부, 미구현·제한사항·개선 아이디어 정리 여부.
6. 최종적으로 구조화된 QA 리포트를 표 형태로 출력한다: `#` / 요구사항 / 판정(✅⚠️❌) / 근거 또는 확인 방법. 마지막에 "다음에 할 일" 요약(⚠️·❌ 항목 위주)을 덧붙인다.
