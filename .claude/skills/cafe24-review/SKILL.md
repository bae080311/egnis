# /cafe24-review

작업 중이거나 커밋 대기 중인 변경사항이 이 과제의 하드 룰을 어기지 않았는지 diff 기준으로 검토한다.

## 절차

1. `.claude/rules/hard-rules.md`를 읽어 절대 금지/필수 준수 항목을 확인한다.
2. `git status`로 변경/미추적 파일을 파악하고, `git diff`(unstaged) + `git diff --cached`(staged) + 필요시 `git diff HEAD`로 실제 변경 내용을 확인한다. 커밋이 하나도 없는 초기 상태라면 현재 워킹트리 전체를 대상으로 본다.
3. 변경분을 하드 룰 항목별로 대조한다:
   - **스코프**: 옵션 영역·옵션 동작이 아닌 곳(상품 이미지, 상세설명, 배너, 구매버튼 외형 등)을 건드린 diff 라인이 있는가?
   - **DOM/이벤트 보존**: `module="product_action"`, `{$action_buy}`, `{$action_basket}`, `{$form.option}`, `{$form.quantity}`, `module="product_option"` 등이 diff에서 삭제되는 방향으로 나타나는가?
   - **구매 로직 재구현**: 새 코드가 카페24 계산/append 로직을 우회하거나 대체하려고 하는가, 아니면 네이티브 컨트롤에 이벤트를 위임(동기화)하는가?
   - **외부 설정 JS 용도**: 설정 JS가 옵션 UI 구성값 관리를 벗어나 구매 로직을 담당하고 있지 않은가?
   - **민감정보**: diff에 `password`, `api key`, `secret`, `token`, `Authorization: Bearer`, 개인 계정 정보로 보이는 문자열이 있는가? (`.claude/hooks/guard-secrets.sh`가 쓰는 패턴과 동일 기준으로 grep)
   - **suffix/횟수 제한, 반응형** 등 구현이 존재한다면 하드 룰의 "반드시 지킬 것" 항목과 부합하는지도 확인한다.
4. 각 항목을 위반(⛔)/의심(⚠️, 수동 확인 필요)/통과(✅)로 표시하고, 위반이 있으면 **어떤 파일의 몇 번째 diff 라인인지** 구체적으로 짚어서 보고한다.
5. 마지막에 결론을 한 줄로 명시한다: "커밋해도 안전함" 또는 "아래 항목부터 고치고 다시 리뷰할 것". 위반이 하나라도 있으면 커밋을 진행하지 말라고 분명히 알린다.

이 스킬은 파일을 수정하지 않는다 — 읽기와 보고만 한다.
