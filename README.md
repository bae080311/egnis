# 카페24 골라담기 옵션 UI 과제

## 파일 구성

```
detail.html                                  수정본 (product/detail.html)
css/module/product/option-picker.css         골라담기 UI 스타일
js/module/product/option-picker.config.js    표시용 설정값 (뱃지/설명/추천문구/문구 포맷)
js/module/product/option-picker.js           동기화 로직
```

카페24 관리자 스마트디자인 편집창에서 `detail.html`을 교체하고, `css`/`js` 두 파일은
스킨 편집창의 파일 업로드(또는 CSS/JS 편집기)에서 위 경로 그대로 올려야
`<!--@css(...)-->` / `<!--@js(...)-->` include가 정상적으로 로드된다.

## 1. 옵션 UI 구현 방식

- 기존 `module="product_option"` 테이블(옵션 select + 수량)은 삭제하지 않고 그대로 둔다.
  다만 옵션 select가 들어있는 첫 `<tr>`에 `optionPickerNativeRow` 클래스를 추가해
  `display:none`으로만 숨긴다(DOM/이벤트는 유지, CSS로만 감춤 — 하드 룰 준수).
- 그 아래 빈 컨테이너 `<div class="optionPicker" id="optionPicker"></div>`를 추가하고,
  `option-picker.js`가 페이지 로드 시 이 컨테이너 안에 골라담기 카드 UI를 렌더링한다.
- 카드 데이터(개입수 티어, 옵션값, 가격)는 하드코딩하지 않고 **네이티브 select의
  `<option>` 목록을 런타임에 파싱**해서 만든다. 즉 카페24 관리자에서 옵션값을
  추가/삭제/가격변경 하면 코드 수정 없이 카드 UI에 자동 반영된다.
- 옵션값 텍스트를 `{개입수}_{순번}` 형태(`10개입_1` 등)로 파싱해 같은 개입수를
  하나의 카드로 묶고, 그 카드 안에 담기(+)/빼기(−) 스테퍼를 둔다. 즉 "옵션값을
  라디오처럼 하나만 고르는" 게 아니라 "개입수 카드에 여러 번 담는" 실제 데이터
  구조(직접입력 + 여러 개 추가)에 맞춘 인터랙션이다.
- 모바일 바텀시트 모달은 채택하지 않고 PC/모바일 모두 인라인 카드 리스트로
  구현했다(아래 "미구현/제한사항" 참고). 구매 버튼과의 겹침 위험을 원천적으로
  없애기 위한 선택이다.
- 색상/타이포/spacing 값은 피그마 시안에서 추출한 `.claude/design/figma-style-tokens.md`
  값을 그대로 사용했다(라디오 자리는 담은 개수를 보여주는 원형 카운터로 대체).

## 2. 외부 설정 JS 구조 (`option-picker.config.js`)

```js
window.OptionPickerConfig = {
  ui: {
    title, subtitle, addButtonLabel, removeButtonLabel,
    limitLabel(max), limitReachedLabel, soldOutLabel,
    unitPriceLabel(unit), emptyListText
  },
  tiers: {
    "10개입": { badge, badgeStrong, description, recommend },
    "30개입": { ... },
    ...
  },
  defaultTier: { badge: null, description: "", recommend: false }
}
```

- `tiers`의 key는 옵션값에서 suffix(`_1`, `_2` ...)를 뗀 문자열과 **정확히 일치**해야
  카드에 반영된다. 일치하는 key가 없으면 `defaultTier` 값으로 대체되어 동작은
  깨지지 않는다(다른 작업자가 신규 개입수를 추가해도 에러 없이 기본 카드로 노출).
- 이 파일에는 **실제 추가 가능 횟수나 가격 숫자를 넣지 않는다.**
  - 추가 가능 횟수는 하드 룰(옵션값 suffix 개수 = 최대 추가 횟수)에 따라
    `option-picker.js`가 select의 `<option>` 개수를 세어 계산한다. config에서
    이 숫자를 바꿀 방법을 의도적으로 열어두지 않았다 — 관리자 옵션값 개수와
    화면 표시가 어긋나는 사고를 막기 위함이다.
  - 가격도 select `<option>` 텍스트에 카페24가 자체적으로 노출하는 가격
    표기(`(+12,000원)` 형태, "옵션가 표시" 설정이 켜져 있을 때)를 정규식으로
    추출해서 쓴다. 즉 관리자에서 가격을 바꾸면 카드 가격도 자동으로 맞는다.
    설정 JS는 그 숫자의 **표시 포맷**(예: 개당가격 문구)만 담당한다.

## 3. 카페24 옵션과 동기화한 방식

- **커스텀 → 네이티브**: 카드의 "담기" 클릭 시, 아직 담기지 않은 suffix 변형 중
  가장 앞 순번을 골라 네이티브 `<select>`의 값을 그 옵션값으로 세팅하고
  `change` 이벤트를 dispatch한다. 실제 담기/가격 계산/"선택 상품 목록" 테이블
  append는 전부 카페24 자체 스크립트가 처리하며, 이 코드는 재구현하지 않는다.
  - 같은 개입수를 연속으로 다시 고를 때 `select.value`가 안 바뀌면 브라우저가
    `change`를 발생시키지 않는 문제가 있어, 값을 빈 문자열로 리셋한 뒤 목표
    값으로 세팅해 매번 실제 값 전환이 일어나도록 처리했다.
  - "빼기"는 직접 행을 지우지 않고, 카페24가 append한 해당 옵션값 행 안의
    삭제 컨트롤(`.option_box_del` 등)을 찾아 `click()`한다. 삭제/재계산 로직도
    카페24 것을 그대로 사용한다.
- **네이티브 → 커스텀**: "선택 상품 목록" 테이블(`상품 목록` caption을 가진
  테이블의 마지막 tbody)을 `MutationObserver`로 감시한다. 행이 추가/삭제될
  때마다 각 옵션값 텍스트가 그 안에 있는지로 담긴 개수를 다시 세어 카드의
  담은 개수/버튼 활성화 상태를 갱신한다. 카페24가 어떤 이유로든(다른 스크립트,
  뒤로가기 등) 목록을 바꿔도 카드 상태가 항상 실제 목록과 일치한다.
- 이 왕복 구조 덕분에 카드를 눌러도, 네이티브 옵션에서 직접 골라도, 목록에서
  직접 삭제해도 항상 같은 상태로 수렴한다(#2, #3 요구사항).

## 4. 체크리스트 QA — 진행 상황과 확인 필요 사항

이 작업은 카페24 관리자/실제 테스트몰 접근 없이 로컬 파일만으로 진행했다.
**아래는 코드 레벨 자체 점검이며, 실제 스토어프론트에 붙여넣은 뒤 시크릿창에서의
동작 확인이 별도로 필요하다.**

| # | 요구사항 | 상태 |
|---|---|---|
| 1 | 골라담기 커스텀 옵션 UI 노출 | 구현함. select의 `<option>`을 못 찾으면 커스텀 UI를 그리지 않고 기본 옵션을 그대로 노출하도록 방어 처리(구매 흐름 차단 방지) |
| 2 | 네이티브 옵션과 선택 상태/구매 흐름 동기화 | 위 3번 항목 방식으로 구현. **실제 렌더링된 select의 마크업(태그명, name/id, 값 형식)을 이 환경에서 직접 확인하지 못했다** — 텍스트버튼 스타일이 실제로도 `<select>` 기반으로 렌더링된다는 전제로 작성함. 실제 몰에서 다르면 `findNativeSelect()` 셀렉터 보정 필요 |
| 3 | 반복 클릭/재선택 시 중복/오류 없음 | select 값 강제 리셋 + MutationObserver 재계산으로 처리. 실제 몰에서 연속 클릭 테스트 필요 |
| 4 | suffix 기준 추가 가능 횟수 제한 | select `<option>` 개수 기반 자동 계산, config로 숫자 변경 불가하게 설계 |
| 5 | 개입 수별 금액 계산 · 품목 모두 생성 | 가격 계산 자체는 카페24 엔진 그대로 사용(재구현 안 함). 카드 가격 표시는 "옵션가 표시" 설정이 켜져 있어야 정상 노출 — 꺼져 있으면 카드에 가격 줄이 생략됨(계산 자체엔 영향 없음) |
| 6 | 수량 변경 / 총금액 / 장바구니 / 바로구매 | 미변경 영역(네이티브 로직 그대로) — 손대지 않음 |
| 7 | 선택 상태 명확히 표시 | 카드 배경색/카운터 강조(피그마 선택 상태 색상) + 스테퍼 숫자로 표시 |
| 8 | 뱃지/설명/추천문구/횟수/가격표시 외부 설정 분리 | `option-picker.config.js` |
| 9 | PC/모바일 반응형 | 인라인 카드 리스트 + 480px 이하 미디어쿼리로 카드 여백/폰트 축소. 개발자도구 모바일 뷰 확인 필요 |

## 5. 미구현 항목 · 제한 사항 · 개선 아이디어

- **실제 카페24 렌더링 DOM을 직접 보지 못한 상태로 작성**했다. "텍스트버튼"
  스타일이 실제로 `<select>` + 스킨 JS 리스킨 형태로 렌더링된다는 일반적인
  카페24 동작 방식을 전제로 `option-picker.js`를 작성했으나, 실제 테스트몰에
  적용 후 브라우저 개발자도구로 옵션 영역 DOM을 확인해 `findNativeSelect()`,
  `findSelectedListBody()`, `clickRowDeleteControl()`의 셀렉터가 실제 마크업과
  맞는지 검증이 꼭 필요하다.
- 피그마 시안의 모바일 "바텀시트" 모달은 구현하지 않고 인라인 카드로 대체했다
  (모달 오버레이가 구매 버튼 영역과 겹칠 위험을 없애기 위한 의도적 선택).
- 가격 카드 표시는 select 옵션 텍스트에 노출된 가격 문자열 파싱에 의존한다.
  관리자 옵션가 표시 설정이 꺼져 있으면 카드에서 가격 줄만 생략되고 기능(담기/
  빼기/횟수 제한)은 정상 동작한다.
- "맛 선택" 같은 2단계 서브패널은 우리 상품 데이터 구조(개입수 suffix 기반,
  맛 종류 없음)와 맞지 않아 가져오지 않았다(`.claude/design/figma-style-tokens.md`
  참고).
- 개선 아이디어: 실제 몰 확인 후 셀렉터를 고정값으로 좁히면(예: select의 실제
  id/name 확인) 방어 로직을 줄이고 더 단순하게 만들 수 있다.
